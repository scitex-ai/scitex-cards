WHY THE LOAD LIVES HERE AND NOWHERE ELSE. `{% templatetag openblock %} load scitex_project_picker {% templatetag closeblock %}` against a library that is not installed is a hard TemplateSyntaxError raised while the template COMPILES — before any view runs, before any context flag is read, before any runtime guard gets a say. A page-level guard therefore cannot save a page that loads this library at its own top level; the page 500s first, and the guard is inert. Putting the load in a partial that is reached ONLY through an `{% templatetag openblock %} include {% templatetag closeblock %}` inside an `{% templatetag openblock %} if {% templatetag closeblock %}` makes the degradation real, because a partial that is never included is never compiled. THIS IS THE FLEET'S SHAPE, NOT A LOCAL INVENTION. scitex-writer carries the same partial for the same measured reason (its `views._project_picker_available`, whose docstring names the hard TemplateSyntaxError verbatim), and the SDK ships `scitex_project_picker` as part of its UI component.
